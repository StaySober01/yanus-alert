# Maple Alert 구조와 구현 계획

현재 진행: 1~2단계 이후 제공된 6장을 추가해 **3단계 로컬 OCR·시간 검증·갱신 추적·주기별 10초 알림을 실험 구현**했다. 솔 야누스 수동 ROI는 사용하지 않으며 미니맵 ROI만 수동 지정한다. 현재 정책/검증/한계는 [TIME_TRACKING.md](TIME_TRACKING.md), 초기 탐색 기록은 [AUTO_DETECTION.md](AUTO_DETECTION.md) 참조. 아래 단계 목록은 개발 로드맵이며 4단계 룬 감지는 아직 미구현이다.

## 원칙 및 구조

React + TypeScript + Vite 로컬 SPA. 백엔드·DB·프레임 업로드 없이 브라우저 내부에서 처리한다. 게임 메모리, 패킷, 파일, 입력 장치에 접근하지 않는다. 화면 공유 오디오는 요청하지 않는다.

```text
src/capture/   공유 수명 관리, 동영상/이미지 공통 Canvas ROI 추출
src/domain/    정규화 좌표 검증·변환 (후속 단계에 상태 추적기)
src/settings/  버전 있는 localStorage 설정 및 손상 데이터 복구
src/analysis/  FrameSource, ImageDetector<T>, Observation<T>, StateTracker 인터페이스
src/audio/     Web Audio 알림 출력
src/ui/        React 화면·사용자 입력·상태 표시
docs/          계획과 샘플 수집 지침
```

후속 분석 흐름: FrameSource → 전체 화면 IconLocator → 자동 ROI → 시간 Detector → StateTracker → 알림 이벤트 → AlertAudio. React에는 감지 알고리즘을 넣지 않는다. 현재 IconLocator는 Worker에 연결되어 있으며 Canvas 크롭 미리보기는 250ms 간격으로 갱신한다. 공유 종료/입력 전환/언마운트 시 정리한다.

## 1단계 — 구현 완료

- 프로젝트 초기화, 화면 공유 시작·중지·브라우저 종료 감지, 선택 취소/오류 안내.
- 두 ROI 드래그·숫자 입력·초기화, 원본 크롭 확인.
- x/y/width/height를 0~1로 저장하고 해상도 변경 시 재투영. UI 배치가 달라지면 재선택 필요.
- localStorage에 ROI/개별 사용 설정/음량 저장. 화면·이미지·공유 권한은 저장하지 않음.
- 로컬 이미지 입력 및 알림음 테스트. 감지는 미구현으로 표시.
- 검증: `npm test`, `npm run build`, README 수동 검증.

## 2단계 — 실제 샘플 수집 및 실험 [샘플 필수]

SAMPLES.md에 따라 원본 화면과 시간 순서가 있는 이미지를 확보한다. 아이콘 크기, 숫자 배치, 배경, 색 분포를 실제로 확인하며 지속 시간·폰트·색 임계값을 미리 확정하지 않는다. 라벨이 있는 샘플을 개발/검증 집합으로 분리한다. 현재 CanvasFrameSource는 HTMLVideoElement와 HTMLImageElement를 동일 경로로 처리하므로 후속 이미지 회귀 테스트에도 사용한다.

## 3단계 — 솔 야누스 감지 및 추적 [샘플 필수]

아이콘 탐색 → 숫자 영역 추출 → 템플릿 또는 로컬 OCR 비교. 필요할 때 OpenCV.js/Tesseract.js를 추가하고 모델/WASM도 로컬 제공한다. confidence, 유효 범위, 경과 시간의 일관성으로 판독을 검증한다. OCR 실패를 곧바로 소멸로 처리하지 않는다.

미확인/활성/이번 주기 알림 완료/소멸 상태를 분리한다. 검증된 시간이 10초 이하로 내려가면 주기당 한 번 알림. 갱신은 복수 관측으로 확정하고 새 주기를 시작한다. 첫 인식부터 10초 이하인 경우, 일시 누락 허용 시간, 갱신 판정 오차는 샘플 확인 후 정책을 명시한다. 오래된 추정만으로 알림을 확정하지 않는다.

검증: 11→10→9, 중복 10, 갱신, 소멸, OCR 실패/오독, 공유 재시작, 기능 OFF. 단조 증가 시각을 추적기에 주입하여 가상 시간 테스트와 실제 이미지 시퀀스로 검증한다.

## 4단계 — 룬 감지 및 전환 추적 [샘플 필수]

실제 샘플에서 색 후보 마스크, 연결 성분의 크기/종횡비/마름모 형태, 템플릿 점수를 결합한다. 비슷한 표식을 음성 샘플로 검증한다. 연속 양성으로 출현 확정, 연속 음성으로 소멸 확정하며 임계값은 샘플로 조정한다. 확정된 없음→있음 전환마다 한 번 알림.

검증: 유사색의 일시 출현, 룬 유지, 일시 가림, 소멸 후 재출현. 최초 공유부터 룬이 있는 경우 정책도 명시한다.

## 5단계 — 통합과 성능 검증

AbortController와 세션 번호로 이전 비동기 OCR 결과 폐기. 분석 완료 후 다음 작업을 예약해 중복 실행 방지. 공유 종료 시 추적기·대기 작업·알림 정리. CPU/메모리/백그라운드 탭 제약/최소화된 게임 창의 프레임 정지/다양한 해상도/장시간 세션 확인. 필요시 Worker로 분석 이전.
