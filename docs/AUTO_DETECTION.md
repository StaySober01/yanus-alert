# 솔 야누스 자동 위치 탐색 실험

이 문서는 **초기 2단계 당시 기록**이다. 이후 3단계에서 축소 화면 지원, 로컬 OCR, 주기 추적과 알림을 추가했다. 현재 상태는 [TIME_TRACKING.md](TIME_TRACKING.md)를 참조한다.

## 제공된 근거

- 원본 스크린샷: 1918×1081. 사용자가 우상단 솔 야누스 시간을 **47초**로 라벨링.
- 기준 아이콘: 29×32 PNG. `public/templates/sol-yanus.png`로 로컬 제공.
- 이미지 관찰: 숫자와 검정 테두리가 중앙을 가림. 원형 장식의 바깥 부분은 남음. 화면 하단 단축키 영역에도 유사 아이콘이 있으므로 단순 아이콘 일치만으로 버프라고 확정하면 안 됨.

원본 전체 화면은 `samples/private/`에 보관하고 Git/빌드에서 제외했다. `samples/fixtures/`에는 회귀 검증에 쓰는 버프 띠와 단축키 영역만 저장했다. 둘 다 같은 원본에서 파생되었으므로 독립 검증 데이터가 아니다.

## 구현

`CanvasFrameSource → YanusSession → Worker → IconLocator → 정규화된 위치 → UI/크롭`

- 위치를 하드코딩하지 않고 원본 전체 픽셀을 탐색한다.
- 기준 아이콘 외곽과 중앙 숫자 가림 영역을 제외한 픽셀로 평균 밝기 기반 정규화 상관도를 계산한다.
- 노란색 시간 표시 후보의 적분 영상을 먼저 검사하고, 소수 픽셀로 빠른 필터링 후 상세 점수를 계산한다.
- 너비 22, 24, 26, 29, 32, 36, 40, 44, 48, 58px를 탐색한다. 임의 배율 전체를 지원한다는 의미가 아니다.
- 상세 상관도 0.78 이상만 후보. 겹친 후보는 통합하고, 서로 다른 두 후보의 점수 차이가 0.06 미만이면 위치를 확정하지 않는다.
- 점수는 확률이 아니다. 임계값/색 범위는 현재 샘플 기반의 초기값이며 다른 환경 데이터로 조정해야 한다.
- 정지 이미지는 1회, 영상은 작업 완료 후 1초 뒤 재탐색한다. 이전 위치 주변만 찾는 최적화는 아직 도입하지 않았다.
- UI와 별도 Worker에서 실행한다. 공유 종료/입력 전환/크기 변경/기능 OFF/언마운트 때 작업을 종료한다. 병렬로 프레임 분석을 쌓지 않는다.
- 미검출에는 가림/다른 배율/색 변화도 포함되므로 버프 소멸이나 남은 시간 0으로 해석하지 않는다.

## 확인한 결과

- 원본 전체 화면: (1631, 3), 29×32, 상관도 약 0.900455.
- 실제 브라우저 Worker: 원본 입력에서 약 352ms (단일 실행 관측값; 성능 보장/벤치마크 아님).
- 버프 크롭, 다른 화면 위치로 이동, 아이콘 제거, 단축키 영역, 빈 프레임, 동일 후보 2개, 합성 최근접 2배 확대 테스트 통과.
- 프레임 작업 중복 방지, 정지 이미지 단일 실행, 종료 후 늦은 응답 무시, Worker 오류 처리 테스트 통과.

## 이번 단계에서 하지 않은 것

**OCR, 숫자 템플릿 판독, 버프 주기 추적, 10초 알림은 연결하지 않았다.** 프로그램에 47이라는 값을 넣어서 인식 결과처럼 표시하지 않는다. 원본에서 찾은 아이콘의 크롭에는 숫자가 그대로 보여 사람이 위치 정확성을 확인할 수 있다.

다음에는 11/10/9초, 한 자리 숫자, 갱신 전후, 다른 배율/배치의 원본 이미지가 필요하다. 가능하면 0~9 숫자가 모두 포함된 시간대의 연속 샘플을 확보한다. 같은 샘플에 맞춘 결과만으로 판독 정확도를 주장하지 않고 별도 장면으로 검증한다. 숫자 판독 실패/갱신/소멸을 처리하는 추적기를 구현한 뒤 자동 알림을 연결한다.
